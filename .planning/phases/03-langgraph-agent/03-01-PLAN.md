<feature>
  <name>PropertyListing model + URL builder + listing parser</name>
  <files>agent/models.py, agent/url_builder.py, tests/test_url_builder.py, tests/test_parser.py</files>
  <behavior>
    build_search_url cases:
    - build_search_url("richmond-vic") -> "https://www.domain.com.au/rent/richmond-vic/?page=1"
    - build_search_url("richmond-vic", bedrooms_min=2) -> URL contains "bedrooms=2-any"
    - build_search_url("richmond-vic", bathrooms_min=1) -> URL contains "bathrooms=1-any"
    - build_search_url("richmond-vic", price_min=500, price_max=2000) -> URL contains "price=500-2000"
    - build_search_url("richmond-vic", property_type="apartment") -> URL contains "ptype=apartment-unit-flat"
    - build_search_url("richmond-vic", property_type="house") -> URL contains "ptype=house"
    - build_search_url("Richmond VIC 3121", page=2) -> slug is "richmond-vic-3121", page=2 in URL
    - build_search_url("richmond-vic", bedrooms_min=0) when bedrooms_min=None -> no bedrooms param
    - build_search_url("richmond-vic", price_max=2000) with no price_min -> price=0-2000

    parse_listings_from_message cases:
    - Valid JSON string -> List[PropertyListing] with all parsed fields
    - JSON wrapped in ```json ... ``` fences -> fences stripped, parsed correctly
    - JSON with bot_detected=true -> raises BotDetectedError
    - JSON with listings where address+listing_url missing -> listing excluded from result
    - JSON with missing optional fields (price=null) -> PropertyListing with price=None
    - Malformed JSON with recoverable pattern -> extract via regex fallback
    - Completely unparseable content -> return empty list (do not raise)
    - Multimodal content (list of blocks with "text" key) -> extract text, then parse
  </behavior>
  <implementation>
    agent/models.py:
      - Import BaseModel from pydantic
      - Define PropertyListing with fields: address: str, listing_url: str, price: str | None = None,
        bedrooms: int | None = None, bathrooms: int | None = None, property_type: str | None = None
      - Add is_valid() method: returns bool(self.address and self.listing_url)

    agent/url_builder.py:
      - Import urlencode from urllib.parse
      - Define PROPERTY_TYPE_MAP dict mapping colloquial names to domain.com.au ptype values:
        "apartment"/"unit"/"flat" -> "apartment-unit-flat", "house" -> "house",
        "townhouse" -> "townhouse", "studio" -> "studio"
      - Define build_search_url(suburb, page=1, bedrooms_min=None, bathrooms_min=None,
        price_min=None, price_max=None, property_type=None) -> str
        - slug = suburb.lower().replace(" ", "-")
        - base = f"https://www.domain.com.au/rent/{slug}/"
        - Build params dict — only add bedrooms/bathrooms/price/ptype if not None
        - Always add page param
        - Return f"{base}?{urlencode(params)}"
      - Define parse_listings_from_message(content: str | list) -> list[PropertyListing]:
        - Handle list content: join text blocks (content[i]["text"] for blocks with type "text")
        - Strip markdown code fences: re.sub(r"```(?:json)?\s*", "", text).strip()
        - Try json.loads(text)
        - Fallback: re.search(r"\{.*\}", text, re.DOTALL) then json.loads on match
        - If neither works: return []
        - Check data.get("bot_detected") — if True, raise BotDetectedError
        - Parse data.get("listings", []) into PropertyListing models
        - Skip listings where is_valid() is False
        - Note: BotDetectedError imported from agent.exceptions (created in Plan 02, but
          since plans run in same wave, import is deferred to runtime — use TYPE_CHECKING guard
          or import inside the function to avoid circular/missing import at test time)

    Important: parse_listings_from_message imports BotDetectedError inside the function body
    (not at module level) to avoid import errors when agent/exceptions.py doesn't exist yet.
    This is acceptable for Phase 3 — Phase 4 will not change this file.
  </implementation>
</feature>
