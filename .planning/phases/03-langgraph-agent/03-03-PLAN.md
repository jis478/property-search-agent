<task type="auto">
  <name>Task 1: property_agent.py — agent construction and invocation</name>
  <files>agent/property_agent.py</files>
  <action>
    Create `agent/property_agent.py` implementing two async functions:

    **build_agent(mcp_tools: list) -> CompiledGraph:**
    - Import: `from langgraph.prebuilt import create_react_agent`
    - Import: `from langchain_openai import ChatOpenAI`
    - Import: `from agent.prompts import SYSTEM_PROMPT`
    - Filter tools: `REQUIRED_TOOLS = {"browser_navigate", "browser_take_screenshot", "browser_wait_for"}`
      `agent_tools = [t for t in mcp_tools if t.name in REQUIRED_TOOLS]`
    - Create LLM: `ChatOpenAI(model="gpt-4o", temperature=0)`
    - Return: `create_react_agent(model=llm, tools=agent_tools, prompt=SYSTEM_PROMPT, recursion_limit=15)`
    - Per research: LangGraph counts reasoning supersteps as well as tool calls. 3 pages × (navigate + wait + screenshot) = 9 tool calls, plus reasoning steps between each tool exceeds 10. recursion_limit=15 is the practical minimum while honoring AGNT-01's intent ("prevent infinite loops, keep browser tool calls ≤ 10"). Document this in a comment.

    **search_properties(agent, query: str) -> list[PropertyListing]:**
    - Import: `from langgraph.errors import GraphRecursionError`
    - Import: `from agent.exceptions import StepLimitError, BotDetectedError`
    - Import: `from agent.url_builder import parse_listings_from_message`
    - Import: `from agent.models import PropertyListing`
    - Call: `result = await agent.ainvoke({"messages": [{"role": "user", "content": query}]})`
    - Wrap in try/except GraphRecursionError: re-raise as StepLimitError
    - Extract final message: `final_message = result["messages"][-1]`
    - Call `parse_listings_from_message(final_message.content)` to get `List[PropertyListing]`
    - Return the list (BotDetectedError propagates up naturally from parse_listings_from_message — AGNT-04)
    - Return type annotation: `list[PropertyListing]`

    **Partial results pattern** (CONTEXT.md locked decision):
    - CONTEXT.md: "Partial failure mid-run (e.g., page 1 ok, page 2 bot-detected) → return collected listings so far"
    - Implementation: `parse_listings_from_message` in url_builder.py (Plan 01) handles this:
      - bot_detected=false → return all listings
      - bot_detected=true AND listings non-empty → return collected listings (partial — NOT an error)
      - bot_detected=true AND listings empty → raise BotDetectedError
    - Plan 01's `parse_listings_from_message` must implement this partial-results contract.
      The executor for Plan 01 MUST read Plan 03-03 (this plan) so it understands the expected
      behaviour before writing the parser. (Plan 03-01 SUMMARY will be available as context.)
    - The agent delegates all JSON parsing and bot detection entirely to `parse_listings_from_message`.
      No inline JSON parsing in `search_properties` — the tested function owns all of this logic.

    Add module-level docstring explaining the two functions and their error contract.
  </action>
