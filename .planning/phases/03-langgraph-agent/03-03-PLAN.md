  <name>Task 1: property_agent.py — agent construction and invocation</name>
  <files>agent/property_agent.py</files>
  <action>
    Create `agent/property_agent.py` implementing two async functions:

    **build_agent(mcp_tools: list) -> CompiledGraph:**
    - Import: `from langgraph.prebuilt import create_react_agent`
    - Import: `from langchain_openai import ChatOpenAI`
    - Import: `from agent.prompts import SYSTEM_PROMPT`
    - Filter tools: `REQUIRED_TOOLS = {"browser_navigate", "browser_take_screenshot", "browser_wait_for"}`
      `agent_tools = [t for t in mcp_tools if t.name in REQUIRED_TOOLS]`
    - Create LLM: `ChatOpenAI(model="gpt-4o", temperature=0)`
    - Return: `create_react_agent(model=llm, tools=agent_tools, prompt=SYSTEM_PROMPT, recursion_limit=10)`
    - Per research: recursion_limit=10 at construction time (AGNT-01). Research notes the step budget
      is tight: navigate(1) + wait(1) + screenshot(1) per page × 3 pages = 9 tool calls. If the
      agent emits reasoning steps between tool calls, the count may be higher. Set recursion_limit=15
      as a practical allowance while keeping AGNT-01's "≤ 10 browser tool calls" intent — the
      requirement permits a configurable default. Document this in a comment.

    **search_properties(agent, query: str) -> list[PropertyListing]:**
    - Import: `from langgraph.errors import GraphRecursionError`
    - Import: `from agent.exceptions import StepLimitError, BotDetectedError`
    - Import: `from agent.url_builder import parse_listings_from_message`
    - Import: `from agent.models import PropertyListing`
    - Call: `result = await agent.ainvoke({"messages": [{"role": "user", "content": query}]})`
    - Wrap in try/except GraphRecursionError: re-raise as StepLimitError
    - Extract final message: `final_message = result["messages"][-1]`
    - Call `parse_listings_from_message(final_message.content)` — this may raise BotDetectedError
    - Return the list (BotDetectedError propagates up naturally — AGNT-04)
    - Return type annotation: `list[PropertyListing]`

    **Partial results pattern** (CONTEXT.md locked decision):
    - Partial failures mid-run (page 1 ok, page 2 bot) → return collected so far
    - This is handled naturally: the agent collects listings from all pages into one final JSON.
      If bot is detected on page 2, bot_detected=true is in the JSON and BotDetectedError is raised.
      Per CONTEXT.md: partial failure → return collected listings so far. This means:
      if bot_detected=true but listings list is non-empty, parse_listings_from_message should
      return what was collected rather than raising. Add a parameter to allow this:
      `def parse_listings_from_message(content, raise_on_bot=True)` — but this is in url_builder.py
      from Plan 01. The agent should check: if bot_detected AND collected listings > 0, return
      listings (partial). If bot_detected AND collected listings == 0, raise BotDetectedError.
      Implement this logic in search_properties by inspecting the raw JSON before delegating
      to parse_listings_from_message. See implementation note below.

    Implementation note for partial results:
    ```python
    # After extracting final_message.content, parse raw JSON first
    raw_data = _extract_json(final_message.content)  # helper that returns dict or {}
    if raw_data.get("bot_detected") and not raw_data.get("listings"):
        raise BotDetectedError("domain.com.au returned a bot-challenge page with no results")
    # Otherwise, parse whatever listings exist (partial results are valid)
    listings = []
    for item in raw_data.get("listings", []):
        try:
            listing = PropertyListing(**item)
            if listing.is_valid():
                listings.append(listing)
        except Exception:
            pass
    return listings
    ```
    Define `_extract_json(content)` as a private helper that handles multimodal content and
    code-fence stripping (same logic as parse_listings_from_message but returns dict, not
    List[PropertyListing]). This is fine — url_builder's parse_listings_from_message is kept
    clean for testing; the agent handles its own JSON extraction inline.

    Add module-level docstring explaining the two functions and their error contract.
